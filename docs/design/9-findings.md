## Fixture artifacts

Differences below are caused by the synthetic fixture data used to drive this comparison, not by the product itself — do not treat these as findings for task 4.

- **Run status is "killed" with an error, not a clean "completed" return.** `fixtures/workflow-run.json`'s `status` is `"killed"` and it carries an `error` field with a stack trace; `result` is `null`. Artboard 9c depicts a clean successful return (a 2,140-word brief). Even if the "Returned" box existed today, this exact fixture wouldn't populate it with prose — this is why row #3 above is evaluated against the *absence* of the box rather than its content correctness.
- **The seeded "finished" run is mid-`Build`, not fully finished.** One agent (`a2a07e2a8ef27d692`) is still `progress`/`running` in the fixture's `workflowProgress`, so the "collapsed phases" comparison in row #4 is against a run that's genuinely still showing an open phase — a true fully-`done` fixture would be needed to rule out a collapse behavior that only triggers once every phase is `returned`.
- **The live demo run (`wf_live00-demo`) is hand-authored, not a captured real journal.** Its 9 agent ids are a mix of the 4 real fixture ids (reused from `workflow-agent-usage.json`) and 5 synthetic placeholders (`alive00demo...`–`alive04demo...`); none carry realistic URLs, spec paths, or labels the way the design's `fda.gov`/`spec/auth.spec.ts` rows do. The *shape* of the flat-table degradation (row #1) is real and load-bearing; the specific id/label values are not meaningful to compare.
- **Scale mismatch.** The design's deep-research run has 36-37 agents across 5 phases; the seeded finished run has 4 agents across 3 phases, and the live demo has 9. This affects only which rows are visible (e.g. "+N more" truncation genuinely can't be exercised with only 2-agent dispatch groups), not the underlying gap findings.
- **ITEM GRID toggle didn't activate.** Clicking `ITEM GRID` on the seeded finished run left the view on `BY PHASE` with no visible change — likely because `gridCooperates()` requires item keys that resolve across phases, which this fixture's data doesn't provide (its agents are per-phase-unique `S1-server`/`S2-client` labels, not shared work items like 9b's spec files). This means row #16 (the shared-item trail icon) couldn't be visually confirmed either way against a live grid render, though the inventory's static-code read already establishes it's unbuilt.
- **`usage` and `agents` tabs have no design counterpart to diff against.** Artboard 9 only shows the tab strip existing (row #8); it never depicts what those two tabs contain, so `9-implemented-usage-tab.png` and `9-implemented-agents-tab.png` are included for task 4's context but generate no findings rows of their own.
